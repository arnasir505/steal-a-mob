# Проект игры — работа через VS Code, Rojo и Claude Code

## Что тут лежит

- `src/` — весь код игры.
- `default.project.json` — настройки Rojo: какая папка куда попадает в Studio.
- `CLAUDE.md` — все решения по дизайну и правила проекта. Claude Code читает его сам
  при запуске, поэтому знает, что мы уже придумали. Обновляй его, когда что-то меняется.

## Установка (один раз)

1. Установи **VS Code**.
2. В VS Code открой вкладку Extensions и установи:
   - **Rojo** (синхронизация с Roblox Studio);
   - **Luau Language Server** (подсказки и проверка ошибок в коде);
   - **Claude Code**.
3. Распакуй этот архив в удобную папку и открой её в VS Code (**File → Open Folder**).
4. В Roblox Studio установи плагин **Rojo** (через расширение в VS Code есть кнопка установки
   плагина, или найди Rojo в Creator Store).

## Перенос проекта в Rojo (один раз)

Код, который ты вставлял вручную, теперь будет приходить из этих файлов.

1. Сохрани копию своего места в Studio на всякий случай (**File → Save to File As**).
2. Удали вручную созданные объекты с кодом:
   `ReplicatedStorage → Shared`, `ServerScriptService → Main`, `TestCommands`, `Services`.
   Модели и всё остальное **не трогай**.
3. В VS Code запусти Rojo (через расширение: **Rojo: Open menu → Start server**).
4. В Studio открой плагин Rojo и нажми **Connect**.
5. Код появится в Studio. Нажми Play и проверь `!money 1000`.

## Новое место с нуля (если старое недоступно)

Код лежит файлами, поэтому перенести проект в новое место — пять минут.

1. Studio → **New** → Baseplate → **File → Publish to Roblox As** → Create new experience.
2. **File → Game Settings → Security** → включить **Enable Studio Access to API Services**.
   Без этого сохранение данных игроков работать не будет.
3. Там же **Places → Servers → Max Players** поставь **не больше 12**.
   Игра строит 12 временных участков (`GameConfig.Plot.TempCount`), по одному на игрока.
   Хочешь больше игроков — подними это число в конфиге.
4. Запусти Rojo в VS Code, в Studio нажми **Connect** — код приедет сам.
5. Нажми Play и проверь `!egg`.

Что НЕ переедет само: модели, которые ты делал в Studio (их надо скопировать из старого
места через **File → Save to File As**), и сохранения игроков — в новом месте своё
хранилище данных, прогресс начнётся с нуля. Для разработки это нормально.

Старое место **не удаляй**: доступ к нему может вернуться, и модели оттуда можно будет забрать.

## Как работать дальше

- Открываешь папку в VS Code, запускаешь Rojo, подключаешься в Studio.
- Пишешь задачу в Claude Code (например: «Сделай этап 2 из CLAUDE.md»).
- Claude Code меняет файлы, Rojo сам переносит изменения в Studio.
- Модели делаешь прямо в Studio — Rojo их не трогает.
- Код меняй только в VS Code: правки скриптов прямо в Studio Rojo перезапишет.

## Как играть прямо сейчас (этап 2)

Нажми Play в Studio. Тебя поставит на твой участок (пока это временные кубики).

1. Напиши в чат `!egg` — в рюкзак упадёт случайное яйцо.
2. Встань в любом месте внутри забора и нажми **E** — яйцо встанет там, где ты стоишь,
   и над ним пойдёт таймер вылупления. Модель повернётся туда же, куда смотришь ты.
3. Дождись таймера (или напиши `!hatch`) — вылупится моб и начнёт приносить деньги.
   Доход виден в таблице лидеров в колонке `Income/s`.
4. Подойди к поставленному предмету: **E** — убрать в рюкзак, **F** — продать.
5. У жёлтой тумбы нажми **E** — улучшить участок. Станет больше мест, забор станет лучше.

Сколько предметов помещается, показывает табличка у входа. Слотов-плиток на земле нет:
ставь куда хочешь, лишь бы внутри забора и не вплотную к другому предмету.

Всё считает сервер: и куда именно встало яйцо, и деньги, и доход, и вылупление.
Клиент только просит «поставить» — позицию сервер берёт сам, поэтому поставить яйцо
на чужой участок или сквозь забор не получится.
Яйца вылупляются и пока ты офлайн: хранится не «сколько осталось», а дата вылупления.

## Скорость (этап 3)

Рядом со входом на участок стоит тёмная плита — **беговая дорожка**.

1. Встань на неё и стой: скорость растёт, пока ты на ней. Видно в таблице лидеров
   в колонке `Speed`.
2. Нажми **E** у дорожки — улучшить её за деньги. Чем выше уровень, тем больше
   скорости в секунду. На табличке написано, сколько сейчас капает и сколько стоит.
3. `!trail` покажет список трейлов, `!trail BlueTrail` купит и наденет,
   `!equip off` снимет. Трейл даёт множитель к дорожке и виден за спиной.
   Магазина трейлов пока нет — он появится вместе с интерфейсом на этапе 11.
4. `!speedinfo` разложит скорость по частям: стата, геймпасс, вес яйца, WalkSpeed.

Стата скорости растёт бесконечно, а настоящая скорость персонажа — нет: она растёт
логарифмически и упирается в предел 350. Каждые x10 к стате дают +16 к WalkSpeed.
Исход погони от босса будет решать именно стата, а не WalkSpeed.

**Важно для твоих моделей:** на скорости 350 персонаж проходит около 6 студов за кадр,
поэтому любую деталь тоньше 8 студов он может проскочить насквозь. Ворота биомов,
границы safe zone и стены делай толстыми. Если по виду нужен тонкий забор — поставь
позади него невидимую толстую стену (Transparency = 1, CanCollide = true).
Числа кривой лежат в `GameConfig.Speed`, их можно менять без правки кода:
`!formulas` покажет всю таблицу скоростей.

Сервер каждые полсекунды проверяет, не переместился ли игрок дальше, чем разрешает
его скорость. Если да — возвращает назад. Честные телепорты (появление на участке,
сброс раунда, отталкивание боссом) сервис знает и не считает нарушением.

## Свои модели вместо временных кубиков

Временные кубики создаются только пока в игре нет твоих моделей.

- **Участки.** Сделай в Workspace папку `Plots`, в ней модели `Plot1`, `Plot2`, ... (по одной
  на игрока). Внутри каждой модели:
  - `Floor` — **обязательно.** Пол участка. По нему игра понимает, где можно ставить яйца.
  - `Spawn` — где появляется хозяин участка.
  - `Sign` — необязательно. На ней появится имя владельца и число мест.
  - `Upgrade` — необязательно. Тумба, у которой покупают улучшение. Если её нет,
    улучшение покупается у таблички.
  - `Treadmill` — необязательно. Беговая дорожка: пока игрок стоит на ней, скорость
    растёт. Улучшается там же за деньги.
  - `Fences` — необязательно. Папка с моделями заборов: `Fence0`, `Fence3`, `Fence7`...
    Число в имени — с какого уровня улучшения показывать этот забор. Если папки нет,
    игра строит простой забор из столбиков и меняет его вид сама.

  Деталей под слоты делать **не нужно**.
- **Яйца и мобы.** Папки `ReplicatedStorage.Assets.Eggs` и `ReplicatedStorage.Assets.Mobs`,
  имена моделей — как в `Config/Mobs.luau` (`ModelName` и `EggModelName`).
  У каждой модели обязательно выстави **PrimaryPart**, иначе модель не встанет на участок.
  Размер модели игра меняет сама: чем тяжелее моб, тем он больше.

## Тестовые команды (только в Studio)

| Команда | Что делает |
|---|---|
| `!money 1000` | дать денег |
| `!speed 500` | дать скорости |
| `!spend 300` | потратить деньги |
| `!egg` | положить в рюкзак случайное яйцо |
| `!egg Cow Rare 500` | яйцо конкретного моба, редкости и веса (слова в любом порядке) |
| `!mob` | положить в рюкзак случайного моба |
| `!rarities` | показать шансы редкостей по биомам и шансы мутаций |
| `!bag` | показать рюкзак в Output |
| `!plot` | показать участок и доход в Output |
| `!hatch` | вылупить все яйца на участке прямо сейчас |
| `!slots 3` | поднять уровень участка бесплатно |
| `!sell` | продать всё из рюкзака (`!sell eggs` / `!sell mobs`) |
| `!treadmill 5` | поднять уровень дорожки бесплатно |
| `!trail` | список трейлов (`!trail BlueTrail` — купить и надеть) |
| `!equip off` | снять трейл |
| `!speedinfo` | показать, из чего складывается скорость |
| `!data` | вывести данные в Output |
| `!formulas` | вывести примеры формул в Output |
| `!wipe` | сбросить прогресс |

Сохранение работает только в опубликованном месте с включённым
**Game Settings → Security → Enable Studio Access to API Services**.
