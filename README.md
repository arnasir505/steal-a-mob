# Проект игры — работа через VS Code, Rojo и Claude Code

## Что тут лежит

- `src/` — весь код игры.
- `default.project.json` — настройки Rojo: какая папка куда попадает в Studio.
- `CLAUDE.md` — все решения по дизайну и правила проекта. Claude Code читает его сам
  при запуске, поэтому знает, что мы уже придумали. Обновляй его, когда что-то меняется.

## Установка (один раз)

1. Установи **VS Code**.
2. В VS Code открой вкладку Extensions и установи:
   - **Rojo** (синхронизация с Roblox Studio);
   - **Luau Language Server** (подсказки и проверка ошибок в коде);
   - **Claude Code**.
3. Распакуй этот архив в удобную папку и открой её в VS Code (**File → Open Folder**).
4. В Roblox Studio установи плагин **Rojo** (через расширение в VS Code есть кнопка установки
   плагина, или найди Rojo в Creator Store).

## Перенос проекта в Rojo (один раз)

Код, который ты вставлял вручную, теперь будет приходить из этих файлов.

1. Сохрани копию своего места в Studio на всякий случай (**File → Save to File As**).
2. Удали вручную созданные объекты с кодом:
   `ReplicatedStorage → Shared`, `ServerScriptService → Main`, `TestCommands`, `Services`.
   Модели и всё остальное **не трогай**.
3. В VS Code запусти Rojo (через расширение: **Rojo: Open menu → Start server**).
4. В Studio открой плагин Rojo и нажми **Connect**.
5. Код появится в Studio. Нажми Play и проверь `!money 1000`.

## Новое место с нуля (если старое недоступно)

Код лежит файлами, поэтому перенести проект в новое место — пять минут.

1. Studio → **New** → Baseplate → **File → Publish to Roblox As** → Create new experience.
2. **File → Game Settings → Security** → включить **Enable Studio Access to API Services**.
   Без этого сохранение данных игроков работать не будет.
3. Там же **Places → Servers → Max Players** поставь **не больше 12**.
   Игра строит 12 временных участков (`GameConfig.Plot.TempCount`), по одному на игрока.
   Хочешь больше игроков — подними это число в конфиге.
4. Запусти Rojo в VS Code, в Studio нажми **Connect** — код приедет сам.
5. Нажми Play и проверь `!egg`.

Что НЕ переедет само: модели, которые ты делал в Studio (их надо скопировать из старого
места через **File → Save to File As**), и сохранения игроков — в новом месте своё
хранилище данных, прогресс начнётся с нуля. Для разработки это нормально.

Старое место **не удаляй**: доступ к нему может вернуться, и модели оттуда можно будет забрать.

## Как работать дальше

- Открываешь папку в VS Code, запускаешь Rojo, подключаешься в Studio.
- Пишешь задачу в Claude Code (например: «Сделай этап 2 из CLAUDE.md»).
- Claude Code меняет файлы, Rojo сам переносит изменения в Studio.
- Модели делаешь прямо в Studio — Rojo их не трогает.
- Код меняй только в VS Code: правки скриптов прямо в Studio Rojo перезапишет.

## Как играть прямо сейчас (этап 2)

Нажми Play в Studio. Тебя поставит на твой участок (пока это временные кубики).

1. Напиши в чат `!egg` — в рюкзак упадёт случайное яйцо.
2. Встань в любом месте внутри забора и нажми **E** — яйцо встанет там, где ты стоишь,
   и над ним пойдёт таймер вылупления. Модель повернётся туда же, куда смотришь ты.
3. Дождись таймера (или напиши `!hatch`) — вылупится моб и начнёт приносить деньги.
   Доход виден в таблице лидеров в колонке `Income/s`.
4. Подойди к поставленному предмету: **E** — убрать в рюкзак, **F** — продать.
5. У жёлтой тумбы нажми **E** — улучшить участок. Станет больше мест, забор станет лучше.

Сколько предметов помещается, показывает табличка у входа. Слотов-плиток на земле нет:
ставь куда хочешь, лишь бы внутри забора и не вплотную к другому предмету.

Всё считает сервер: и куда именно встало яйцо, и деньги, и доход, и вылупление.
Клиент только просит «поставить» — позицию сервер берёт сам, поэтому поставить яйцо
на чужой участок или сквозь забор не получится.
Яйца вылупляются и пока ты офлайн: хранится не «сколько осталось», а дата вылупления.

## Скорость (этап 3)

Рядом со входом на участок стоит тёмная плита — **беговая дорожка**.

1. Встань на неё — персонаж прилипнет к полотну и побежит на месте. Каждые 0.2 секунды
   капает скорость, над головой всплывает цифра и падает вниз.
   **Чтобы сойти — прыгни** (пробел или кнопка прыжка на телефоне).
2. Нажми **E** у дорожки — улучшить её за деньги. Чем выше уровень, тем больше
   скорости в секунду. На табличке написано, сколько сейчас капает и сколько стоит.
3. `!trail` покажет список трейлов, `!trail BlueTrail` купит и наденет,
   `!equip off` снимет. Трейл даёт множитель к дорожке и виден за спиной.
   Магазина трейлов пока нет — он появится вместе с интерфейсом на этапе 11.
4. `!speedinfo` разложит скорость по частям: стата, геймпасс, вес яйца, WalkSpeed.

Стата скорости растёт бесконечно, а настоящая скорость персонажа — нет: она растёт
логарифмически и упирается в предел 350. Каждые x10 к стате дают +16 к WalkSpeed.
Исход погони от босса будет решать именно стата, а не WalkSpeed.

**Важно для твоих моделей:** на скорости 350 персонаж проходит около 6 студов за кадр,
поэтому любую деталь тоньше 8 студов он может проскочить насквозь. Ворота биомов,
границы safe zone и стены делай толстыми. Если по виду нужен тонкий забор — поставь
позади него невидимую толстую стену (Transparency = 1, CanCollide = true).
Числа кривой лежат в `GameConfig.Speed`, их можно менять без правки кода:
`!formulas` покажет всю таблицу скоростей.

Сервер каждые полсекунды проверяет, не переместился ли игрок дальше, чем разрешает
его скорость. Если да — возвращает назад. Честные телепорты (появление на участке,
сброс раунда, отталкивание боссом) сервис знает и не считает нарушением.

## Свои модели вместо временных кубиков

Временные кубики создаются только пока в игре нет твоих моделей.

- **Участки.** Сделай в Workspace папку `Plots`, в ней модели `Plot1`, `Plot2`, ... (по одной
  на игрока). Всё остальное должно лежать **внутри** модели участка — деталь в Workspace
  рядом игра не увидит, потому что у каждого участка свои табличка, дорожка и забор:

  ```
  Workspace
   └── Plots (Folder)
        └── Plot1 (Model)
             ├── Floor (Part)
             ├── Spawn (Part)
             ├── Sign (Model или Part)
             └── Treadmill (Model или Part)
  ```

  Что игра ищет внутри каждой модели участка:
  - `Floor` — **обязательно.** Пол участка. По нему игра понимает, где можно ставить яйца.
  - `Spawn` — где появляется хозяин участка.
  - `Sign` — необязательно. Имя владельца и число занятых мест. У таблички же
    покупают улучшение базы: над ней висит цена. Может быть деталью или моделью.
  - `Treadmill` — необязательно. Беговая дорожка. Внутри неё:
    - `Treadmill_Floor` — полотно (деталь **или** модель из нескольких деталей).
      По нему считается, где стоит игрок и куда он смотрит. Если его нет,
      берётся габарит всей модели дорожки.
    - `Treadmill_Front` — необязательно. Деталь-указатель: игрок будет бежать
      лицом в её сторону. Без неё он встаёт вдоль длинной стороны полотна,
      в ту сторону, куда шёл.

    **Дорожка меняет вид с уровнем.** `Treadmill` в участке — это модель уровня 0
    и место, где стоит дорожка. Модели следующих уровней положи в папку
    `ReplicatedStorage.Assets.Treadmills` с числом в имени: `Treadmill5`, `Treadmill10`,
    `Treadmill25`... Число — с какого уровня дорожки показывать модель. Копировать их
    в каждый участок не нужно: игра сама поставит нужную модель на место дорожки.
    В каждой модели должно быть своё полотно `Treadmill_Floor` (и, если нужно,
    `Treadmill_Front`). Новая модель встаёт по **PrimaryPart**: сделай у всех моделей
    дорожки (и у той, что в участке) PrimaryPart'ом полотно `Treadmill_Floor` —
    тогда полотно новой модели встанет ровно туда, где было старое.
  - **Забор внутри участка делать не нужно** — игра строит его сама (см. ниже).

  **Участок растёт с уровнем базы.** Передний край (где `Spawn`, табличка и дорожка)
  стоит на месте, а участок растёт назад и в стороны: за каждое улучшение — на одно
  звено забора вглубь и на одно звено с каждого бока. Пол `Floor` растягивается сам.
  Размер на уровне 0 — твой `Floor` как есть.

  **Звено забора.** Положи одно звено (модель или деталь) в папку
  `ReplicatedStorage.Assets.Fences`. Игра сама выложит звенья по всему периметру
  участка любого размера: длинной стороной вдоль края, стороной Front наружу.
  Забор стоит на полу, а пол выступает за его внешнюю сторону на 0.5 студа
  (`FloorOverhang` в `GameConfig.Plot`). Если звенья встают внахлёст, игра пишет
  в Output, какого размера сделать `Floor`, чтобы они легли ровно.
  Хочешь, чтобы забор «красивел», — положи несколько звеньев с числом в имени:
  `Fence0`, `Fence5`, `Fence10` (число = с какого уровня базы).
  Прохода в заборе нет, поэтому сделай забор **без столкновений (CanCollide = false)
  или низким**, чтобы через него можно было перепрыгнуть — иначе хозяин не выйдет
  с участка.

  **Оставь место между участками.** При запуске игра пишет в Output, какого размера
  станет каждый участок на максимуме, например `Plot1: пол 40 x 40, на максимуме
  420 x 230`. Между участками нужно столько места, а `SafeZone` должна накрывать
  участки целиком. Уменьшить рост: `GrowSideSegments`, `GrowDepthSegments`,
  `GrowMaxLevel` в `GameConfig.Plot`.

  Деталей под слоты делать **не нужно**.

  **Свои надписи на табличках.** У `Sign` и `Treadmill` игра сначала ищет
  твою надпись и пишет прямо в неё. Устрой так:

  ```
  Sign (Model или Part)
   └── Board (Part)
        └── SurfaceGui
             └── Label (TextLabel)     <- имя обязательно "Label"
  ```

  Правило простое: **TextLabel назови `Label`**. Если TextLabel в модели всего один,
  имя не важно — игра возьмёт его. Если надписи нет вообще, игра повесит свою
  табличку над деталью, как сейчас на временных кубиках.

  Текст приходит в несколько строк (`Имя\n3 / 6`), поэтому поставь у TextLabel
  `TextWrapped = true` и размер повыше, иначе строки обрежутся.
- **Яйца и мобы.** Папки `ReplicatedStorage.Assets.Eggs` и `ReplicatedStorage.Assets.Mobs`,
  имена моделей — как в `Config/Mobs.luau` (`ModelName` и `EggModelName`).
  Размер модели игра меняет сама: чем тяжелее моб, тем он больше.

  Требования к модели:
  - **PrimaryPart обязателен.** Без него модель не встанет.
  - **PrimaryPart должен быть повёрнут ровно так же, как сама модель** — игра
    поворачивает модель за него. Если PrimaryPart лежит на боку, моб встанет боком.
  - Где именно стоит PrimaryPart (в голове, в лапе, в центре) — **не важно**:
    игра меряет настоящую нижнюю грань модели и ставит её точно на пол.
  - Лицо модели должно смотреть в сторону `-Z` PrimaryPart — тогда моб будет
    повёрнут туда же, куда смотрел игрок, когда ставил яйцо.

## Биомы и раунды (этап 4)

Игра ждёт от карты такую разметку:

```
Workspace
 ├── SafeZone                 деталь ИЛИ модель (внутри детали "Area")
 ├── Biomes (Folder)
 │    └── Plains (Model)      имя = Id биома из Config/Biomes.luau
 │         ├── Area           невидимая деталь-объём биома
 │         ├── Gate           ворота: закрываются на время сброса раунда
 │         └── EggSpawns      папка с деталями-точками спавна яиц
 └── Plots                    участки игроков (внутри SafeZone)
```

Обязательны только `SafeZone` и модель биома. Остального может не быть:

- нет `Area` — границы возьмутся по габариту всей модели биома (грубее, но работает);
- нет `EggSpawns` — точки выбираются случайно внутри биома, пол ищется лучом вниз.
  Луч пропускает зоны `Area`, ворота, игроков и вообще всё, у чего выключены
  столкновения — поэтому яйца не ложатся на невидимые преграды. Но если пол биома
  сам без столкновений, пол не найдётся: тогда расставь точки в `EggSpawns` сам;
- нет `Gate` — проход просто не будет закрываться.

**Про ворота.** Когда проход открыт, игра делает **все** детали внутри `Gate`
прозрачными и убирает у них столкновения; когда закрыт — возвращает их вид
и включает столкновения. Поэтому в `Gate` клади **только саму преграду**:
если положить туда и декоративную арку, она будет исчезать вместе с преградой.
Арку оставь рядом, снаружи `Gate`.

Детали ворот должны быть **Anchored** — иначе при открытии они провалятся сквозь пол
и больше не появятся. Игра это чинит сама и пишет предупреждение в Output.

Проверить ворота, не дожидаясь сброса: `!gates close` и `!gates open`.

Детали `Area` и точки спавна делай невидимыми (`Transparency = 1`) и **обязательно
`CanCollide = false`** — иначе зона работает как стена, игрок в неё не войдёт,
а встанет сверху. При старте сервера в Output будет написано, что найдено, а что нет,
и отдельно — если какая-то зона оказалась сплошной.

`Area` можно делать как угодно по высоте: хоть плоской плитой на полу, хоть высокой
коробкой до потолка. По высоте проверка прощает 60 студов вверх и 15 вниз
(настраивается в `GameConfig.Zone`). Важны только длина и ширина.

Если `!where` говорит «ни в safe zone, ни в биоме», он же печатает разбор:
где ты стоишь, где зона и по какой оси не сошлось.

**Как играет раунд.** Пять минут открыты биомы, в каждом лежит по 5 яиц (общих на всех).
За 10 секунд до конца — предупреждение. Потом все яйца вне рюкзаков пропадают,
всех, кто не в safe zone, телепортирует на свой участок (кто в safe zone или на беговой дорожке, остаётся на месте), ворота закрываются на 3 секунды, спавнятся новые
яйца, ворота открываются.

**Как украсть яйцо.** Подойди к яйцу и **держи E 1 секунду** — оно поднимется над головой.
Тяжёлое яйцо замедляет (видно в `!speedinfo`). Донеси до safe zone — оно само
упадёт в рюкзак. Не успел до конца раунда — яйцо пропало. Нести можно только одно.

Редкие яйца (Mythic и выше) при появлении объявляются всему серверу.

## PvP и мечи (этап 6)

**Как драться.** Возьми меч в панели снизу (клавиша **1**) и кликай. Урона нет — удар роняет противника на полсекунды и
отталкивает. Если у противника в руках яйцо, оно падает на землю, и его может подобрать
кто угодно. Перезарядка удара — 1 секунда.

Правила:
- драться можно только **в биомах** (и тебе, и противнику). В safe zone и на участках нельзя;
- пока несёшь яйцо, бить нельзя: когда берёшь яйцо, меч сам убирается из рук;
- чем реже меч, тем сильнее толкает (`Knockback` в `Config/Items.luau`).

Деревянный меч есть у всех с самого начала (`StarterSword` в `GameConfig.Combat`).
Мечи сильнее будут выдаваться за индекс следующих биомов (`!sword <Id>` — выдать для проверки).

**Модель меча.** Папка `ReplicatedStorage.Assets.Swords`, имя модели — `ModelName`
из `Config/Items.luau` (у деревянного меча — `WoodenSword`). Подойдёт:
- **Tool** с деталью `Handle` внутри — как делают обычные мечи Roblox. Как меч лежит
  в руке, настраивается свойством `Grip` у Tool;
- или **обычная модель** — игра сама сделает из неё Tool. Ручкой станет деталь
  с именем `Handle`, а если её нет — PrimaryPart. Лезвие делай вверх от ручки.

Все детали игра сама скрепит с ручкой. Можно положить внутрь звуки с именами `Swing`
(взмах) и `Hit` (попадание) — они будут играть сами.

**Как проверить одному.** Нужны два игрока: в Studio вкладка **Test** → в поле
**Clients** выбери **2 Players** → **Start**. Откроются два окна игроков. В обоих
у обоих уже есть деревянный меч — зайдите в биом и бейте друг друга.

## Индекс мобов (этап 7)

Индекс — коллекция мобов, которых ты хоть раз получал. Моб открывается, когда
вылупляется на участке или попадает в рюкзак. Редкость не важна: хватит любой Курицы.
Каждый новый моб показывает сообщение, например `Cow — Plains 3/5`.

Открыл всех мобов биома — получаешь меч-награду (`SwordReward` в `Config/Biomes.luau`).
Он сам надевается, если сильнее того, что в руках. У Plains награды нет:
деревянный меч и так начальный.

Мобы, которые у тебя уже были до индекса, засчитаются при следующем входе в игру,
вместе с наградой.

Экрана индекса пока нет — он будет на этапе 11. Посмотреть: `!index`.

## Машина синтеза (этап 8)

Три одинаковых моба (один вид, например три Курицы) превращаются в одного:
- вес — как у самого тяжёлого из трёх, но с шансом 5% моб станет тяжелее в 1.5–3 раза.
  Чем тяжелее моб, тем меньше этот шанс;
- редкость и мутация — как у самого тяжёлого (можно поменять на «лучшее из трёх»:
  `ResultTraits = "Best"` в `GameConfig.Fuse`);
- результат попадает в рюкзак.

Синтезируются только мобы **из рюкзака**: с участка их надо сначала убрать (E у моба).

**Машина.** Поставь в Workspace деталь или модель с именем **`FuseMachine`** — где угодно:
одну в лобби или по одной на каждом участке. На ней появится кнопка **Fuse** (держать E).
Пока нет интерфейса выбора (этап 11), кнопка выбирает сама: вид, которого в рюкзаке
больше всего, и из него три самых дешёвых моба — ценные не пострадают.

Проверить без машины: `!mob Chicken` три раза, потом `!fuse`.

## Удержание игроков (этап 9)

**Бонус друзей.** +10% к доходу и к беговой дорожке за каждого друга на этом же
сервере, максимум +40%. На офлайн-доход не действует. Когда друг заходит или выходит,
приходит сообщение. Проверить одному: `!friends 2` (притвориться, что зашли два друга).

**Ежедневный календарь.** 30 наград за сезон, награды и даты — в `Config/Seasons.luau`.
Каждый новый день (с 00:00 UTC) открывает следующую награду; пропуск дней прогресс
не сбрасывает, но за день — только одна. Новый сезон — календарь с нуля, незабранное
сгорает. Пока нет экрана календаря (этап 11), награда забирается сама через несколько
секунд после входа.

Первый сезон начинается **1 октября 2026**, до этого календаря нет. Проверить раньше:
`!daily skip 4` сдвинет время на 4 дня, потом `!daily next` — получать награду за наградой.

**Таблица лидеров.** Справа сверху — таблица Roblox с игроками этого сервера (первая
колонка — доход в секунду). А общий топ по всем серверам показывается на табло:
поставь в Workspace деталь с именем **`IncomeLeaderboard`** — таблица появится на её
лицевой стороне (Front). Обновляется раз в 2 минуты. Работает только с доступом
к DataStore (в Studio — Game Settings → Security → Enable Studio Access to API Services).

## Донаты (этап 10)

**Что продаётся** (`Config/Products.luau`):
- геймпассы навсегда: `X2Speed`, `X2Hatch`, `X2Money`;
- продукты многоразово: `Speed200K`, `Speed1M` (скорость), `Money30Min`, `Money3Hours`
  (доход за 30 минут / 3 часа, но не меньше `MinMoney`), `InstantHatch`
  (мгновенно вылупить яйцо — кнопка **Hatch Now** у яйца на участке, клавиша **R**).

**Как подключить.** На сайте Roblox: Creator Dashboard → твоя игра → Monetization →
Passes (геймпассы) и Developer Products (продукты). Создай их, укажи цену и впиши
их Id в `Config/Products.luau` вместо `0`. Имена (`Money30Min` и т.д.) не меняй.

**Покупка не потеряется.** Roblox повторяет выдачу, пока игра не подтвердит её, а игра
подтверждает только после того, как сохранила данные игрока. Если игрок вышел или
сервер упал посреди покупки — товар придёт при следующем входе, и ровно один раз.
Мгновенное вылупление не сгорает: если яйцо пропало, покупка ждёт следующего нажатия
Hatch Now.

**Как проверить.** В Studio покупки бесплатные (тестовые), но нужны настоящие Id.
Без Id: `!grant Money30Min` выдаёт продукт тем же путём, что и настоящая покупка,
`!pass X2Money` — будто геймпасс куплен. `!buy` — список и открытие окна покупки.

## Интерфейс (этап 11)

На экране: слева кнопки **Shop** и **Index**, слева снизу скорость (жёлтый «+» открывает
магазин скорости) и деньги с доходом в секунду, справа кнопка **Trails**, справа снизу
таймеры до новых яиц и до ночи. На телефоне скорость/деньги и таймеры уезжают наверх,
чтобы не мешать джойстику и кнопке прыжка.

- **Shop** — вкладки Featured, Speed, Money, Eggs (донаты за Robux, цены берутся с сайта
  Roblox) и Trails (трейлы за игровые деньги).
- **Index** — мобы биома: неоткрытые чёрным силуэтом, открытые в цвете (показываются твои
  3D-модели), прогресс и меч-награда.
- **Погоня** — «RUN!!» сверху и красная рамка, пока гонится босс; кнопка **Drop**, пока несёшь яйцо.

**Картинки.** Id картинок — в `Config/UIAssets.luau`. Новые иконки: сгенерируй лист
по `UI_Screenshots/PROMPTS.md`, положи в `UI_Screenshots/generated/` и запусти
`python tools/cut_ui_art.py` — готовые PNG появятся в `UI_Assets/`.

## Камера

Первое лицо отключено: в `default.project.json` у StarterPlayer стоит
`CameraMinZoomDistance = 8`. Это лечит известный баг Roblox — в первом лице курсор
заперт в центре экрана, и стоит навести его на элемент интерфейса, как камера
перестаёт вращаться и вернуть её нечем.

Если захочешь вернуть первое лицо — поменяй это число на `0.5` (стандарт Roblox).
Но тогда интерфейс на этапе 11 придётся делать аккуратно: ничего кликабельного
в центре экрана, у декоративных Frame `Active = false`, а меню должны сами
освобождать и возвращать курсор.
